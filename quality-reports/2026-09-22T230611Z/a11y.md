# Accessibility: run 2026-09-22T230611Z

**Verdict: ready-with-known-risk. Confidence: medium.** No real screen reader was driven and axe-core was not run.

A keyboard-only user can now log in and manage bugs from start to finish in Chromium and Firefox. Focus moves into each dialog, stays trapped there and comes back when it closes. Rows are real table rows and state is exposed. 19 of the 23 previous findings are fixed. The open risks are: severity badge contrast (a design decision), faint focus rings on the Cancel buttons, the Owner column at 320 px in Chromium, and a few smaller focus and announcement problems. None of them blocks the journey.

Authority: WCAG 2.2 AA. The specs still state no accessibility requirement (a11y-01).

## New

- **a11y-24** (low, confirmed): a failed Create or Edit save drops focus to `<body>`, because the fields are disabled during the request. Tab recovers into the dialog.
- **a11y-25** (medium, confirmed): at 320 px the Owner column (x 281-380) sits outside the region (17-303). In Chromium, keyboard focus does not scroll the region and arrow keys do nothing, because the region has no tabIndex. Firefox scrolls it.
- **a11y-26** (low, confirmed): a second identical "Bug saved. 1 open bug shown." changes nothing in the DOM, so it is not announced. After delete, close and create, the region briefly announces the stale count from before the refetch.
- **a11y-27** (low, gap): the suite has weak guards (`aria-pressed` checked only at load, `row count > 1`, Escape on a closed select, mouse-driven focus-return test). Confirm initial focus, focus after save and delete, the Edit and confirm traps, contrast and reflow are all unguarded, and the suite runs in Chromium only.

## Keyboard path (both engines; logs in evidence/a11y/*/keyboard-path.log)

- **Login.** Focus starts in Username. A wrong login (throwaway username) keeps focus in Username with aria-invalid and aria-describedby set. A good login focuses the h1 and sets "Board – BuggyBoard".
- **Board Tab order.** Search, New Bug, Logout, Open, Closed, the ID/Severity/Title/Owner sort buttons, then one title button per row.
- **New Bug.** Enter focuses Title. The trap wraps both ways. Escape and Close X both return to New Bug. An empty submit keeps focus on Title and marks it invalid. ArrowDown then Escape on Severity keeps the dialog open. Save returns focus to New Bug.
- **Search.** Clear returns focus to the input.
- **Rows and Edit.** Enter or Space on a row's title button opens Edit with focus in Title. Escape and Save return focus to that button. When the row leaves the Open view (the bug was closed), focus goes to the h1.
- **Delete.** Enter on Delete focuses Cancel in the confirm dialog, and Tab cycles only inside it. Escape returns focus to Delete. After the delete is confirmed, focus goes to the h1.
- **Toggle and sort.** After Space on Closed, `aria-pressed` reads Open=false and Closed=true. Sort headers flip `aria-sort` between ascending and descending, and the arrow is aria-hidden.
- **Logout.** Focus lands in Username.
